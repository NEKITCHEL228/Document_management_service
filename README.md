# DocFlow – сервис управления документами

## 1. Назначение проекта
DocFlow – система для централизованного хранения, тематической классификации, контроля версий и отслеживания статуса обработки электронных документов.
Проект развивается поэтапно: консольная версия приложения (ПР3) дополнена веб-интерфейсом на Django (ПР5) и переведена на полноценную систему шаблонов Django Template Language и статических файлов (ПР6).

Приложение позволяет:
* просматривать главную страницу сервиса в браузере;
* просматривать реестр электронных документов с количеством элементов;
* просматривать детальную карточку конкретного документа;
* просматривать категории классификации документов;
* просматривать детальную информацию о категории;
* отслеживать журнал версий документов и проверять статус наличия электронной подписи (ЭЦП);
* валидировать размер файлов версий;
* хранить данные между запусками в JSON-файлах.

## 2. Используемые технологии
* Python 3.11+;
* Django 5.2 – веб-фреймворк;
* Django Template Language (DTL) – шаблонизация веб-страниц;
* HTML5 – семантическая разметка страниц;
* CSS3 и Bootstrap 5.3 – адаптивная верстка и кастомное оформление;
* JavaScript – клиентская динамика (автоматическое определение текущего года);
* JSON для хранения данных;
* pytest – автоматизированное модульное тестирование;
* flake8 – контроль качества и соответствия стандарту PEP 8;
* Git – контроль версий.

## 3. Предметная область
Системы электронного документооборота (СЭД). Обеспечивает жизненный цикл документа от создания черновика и распределения по категориям до контроля редакций, подписания ЭЦП и архивации.

В системе используются основные сущности:
* **Категория (Category)** – тематический раздел для группировки документов (`id`, `name`, `description`).
* **Документ (Document)** – основной информационный объект (`id`, `title`, `content`, `categories`).
* **Пользователь (User)** – автор или редактор документов (`id`, `email`, `password_hash`).
* **Версия (Version)** – редакция документа (`id`, `version_num`, `file_size_mb`, `release_date`, `is_signed`, `author`, `document`).

## 4. Веб-интерфейс и страницы
Веб-часть приложения реализована на Django с использованием Django Template Language. Генерация HTML непосредственно в Python-коде не используется (функция `page()` удалена). Представления подготавливают данные и передают их в шаблоны через контекст.

Основные страницы:
* `/` – главная страница сервиса и навигация (view-функция `index`);
* `/documents/` – реестр документов (view-функция `document_list`);
* `/documents/<int:doc_id>/` – карточка документа (view-функция `document_detail`);
* `/categories/` – список категорий (view-функция `category_list`);
* `/categories/<int:cat_id>/` – информация о категории (view-функция `category_detail`);
* `/versions/` – журнал версий (view-функция `version_list`);
* `/versions/<int:ver_id>/` – карточка редакции и статус ЭЦП (view-функция `version_detail`).

Если объект по указанному ID не найден, возвращается кастомная страница со статусом 404.

## 5. Django Template Language (DTL)

### Базовый шаблон
Общий шаблон для всех страниц:
`my_django_project/templates/base.html`
Он содержит общую разметку документа, подключение Bootstrap 5.3, собственных CSS-стилей и JS-скрипта, навигацию и блоки переопределения:
* `{% block title %}{% endblock %}` – заголовок страницы;
* `{% block content %}{% endblock %}` – основное содержимое.

Дочерние шаблоны наследуют базовый через:
```django
{% extends "base.html" %}
```

### Включаемые шаблоны (include)
Повторяющиеся фрагменты интерфейса вынесены в отдельные подключаемые шаблоны:
* `my_django_project/templates/includes/navigation.html` – главное меню навигации;
* `my_django_project/templates/includes/footer.html` – подвал сайта;
* `my_django_project/templates/documents/includes/document_card.html` – карточка документа;
* `my_django_project/templates/categories/includes/category_card.html` – карточка категории;
* `my_django_project/templates/versions/includes/version_status.html` – бейдж статуса подписания версии ЭЦП.

Подключение выполняется тегом:
```django
{% include "includes/navigation.html" %}
```

### Контекст, циклы и условия
* Данные передаются из view в шаблоны через словарь `context`.
* Итерация по коллекциям выполняется циклом `{% for item in items %}` с обработкой отсутствия записей через `{% empty %}`.
* Ветвления реализованы конструкциями `{% if %}` / `{% else %}` (проверка наличия объекта при 404, проверка статуса ЭЦП и лимита размера файла).

### Фильтры шаблонов
В проекте применены стандартные фильтры DTL:
* `|length` – отображение общего количества документов, категорий и версий (`{{ documents|length }}`);
* `|default` – значения по умолчанию при отсутствии текста (`{{ doc.title|default:"Без названия" }}`);
* `|date:"d.m.Y"` – форматирование даты выпуска версии документа.

## 6. URL-маршрутизация и пространства имён
Для всех приложений настроены пространства имён (`app_name`):
* `homepage:index`
* `documents:list`, `documents:detail`
* `categories:list`, `categories:detail`
* `versions:list`, `versions:detail`

Ссылки в шаблонах формируются динамически с помощью тега `{% url %}`:
```django
<a href="{% url 'documents:detail' doc.id %}">Подробнее</a>
```

## 7. Статические файлы
Статические файлы расположены в каталоге `my_django_project/static/` рядом с каталогом `templates/`:
* `css/style.css` – кастомные стили (оформление карточек `.doc-card`, бейджей статуса ЭЦП, подвала);
* `js/main.js` – клиентский скрипт для динамического отображения текущего года в элементе `#current-year`.

Подключение статики в шаблонах:
```django
{% load static %}
<link rel="stylesheet" href="{% static 'css/style.css' %}">
<script src="{% static 'js/main.js' %}"></script>
```

## 8. Хранение данных
Данные хранятся в JSON-файлах в директории `data/`:
* `data/categories.json`
* `data/documents.json`
* `data/users.json`
* `data/versions.json`

Загрузка и сохранение выполняются функциями модуля `storage.py`. Django ORM на данном этапе не используется.

## 10. Запуск приложения

### Веб-версия (Django):
Перейдите в директорию `my_django_project` и запустите сервер разработки:
```bash
cd my_django_project
python manage.py runserver
```
Веб-интерфейс доступен по адресу: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)

### Консольная версия:
Из корневой папки проекта:
```bash
python main.py
```

pytest -v
