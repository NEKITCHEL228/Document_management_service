# DocFlow – сервис управления документами

## Назначение
DocFlow – система для централизованного хранения, тематической классификации, контроля версий и отслеживания статуса обработки электронных документов.
Консольная версия приложения (ПР3) дополнена веб-интерфейсом на Django (ПР5).

Приложение позволяет:
* просматривать главную страницу сервиса в браузере;
* просматривать реестр электронных документов;
* просматривать детальную карточку конкретного документа;
* просматривать категории классификации документов;
* просматривать детальную информацию о категории;
* отслеживать журнал версий документов и проверять статус наличия электронной подписи (ЭЦП);
* валидировать размер файлов версий;
* хранить данные между запусками в JSON-файлах.

## Используемые технологии
* Python 3.11+;
* Django 5.2 – веб-фреймворк;
* HTML5 – семантическая разметка страниц;
* Bootstrap 5.3 (CDN) – адаптивная верстка и оформление интерфейса;
* pytest – автоматизированное модульное тестирование;
* flake8 – контроль качества и соответствия стандарту PEP 8.

## Целевая аудитория
* Сотрудники организаций (делопроизводство, бухгалтерия, юридический отдел);
* Руководители подразделений, согласующие документацию;
* Команды и специалисты, работающие с договорами, приказами и актами.

## Предметная область
Системы электронного документооборота (СЭД). Обеспечивает жизненный цикл документа от создания черновика и распределения по категориям до контроля редакций, подписания ЭЦП и архивации.

## Основные сущности

### Category – категория
Представляет тематический раздел для группировки документов.
* **Атрибуты:** `id`, `name`, `description`.
* **Методы:** строковое представление `__str__()`.

### Document – документ
Основной информационный объект системы.
* **Атрибуты:** `id`, `title`, `content`, `categories` (список объектов `Category`).
* **Методы:** добавление категории, строковое представление `__str__()`.

### User – пользователь
Автор или редактор документов.
* **Атрибуты:** `id`, `email`, `password_hash`.
* **Методы:** `hash_password()`, проверка доступа.

### Version – версия документа
Конкретная редакция файла документа.
* **Атрибуты:** `id`, `version_num`, `file_size_mb`, `release_date`, `is_signed`, `author` (объект `User`), `document` (объект `Document`).
* **Методы:** `is_valid_size()`, `sign()`, `__str__()`.

## Страницы веб-интерфейса
* `/` – главная страница сервиса и навигация (view-функция `index()`);
* `/documents/` – реестр документов: объекты `Document` из `data/documents.json` (view-функция `document_list()`);
* `/documents/<int:doc_id>/` – карточка документа (view-функция `document_detail()`);
* `/categories/` – список категорий из `data/categories.json` (view-функция `category_list()`);
* `/categories/<int:cat_id>/` – информация о категории (view-функция `category_detail()`);
* `/versions/` – журнал версий из `data/versions.json` (view-функция `version_list()`);
* `/versions/<int:ver_id>/` – карточка редакции и статус ЭЦП (view-функция `version_detail()`).

Если запрашиваемый объект по указанному ID не найден, возвращается кастомная страница с HTTP-кодом 404 (`page_not_found`).

## Основные операции

### Реализовано в веб-интерфейсе (ПР5)
* просмотр списка документов и их категорий;
* просмотр детальной информации по выбранному документу;
* просмотр тематических разделов (категорий);
* просмотр истории версий документов и статуса их подписания;
* централизованная обработка ошибки 404 с возвратом на главную;
* навигация между всеми разделами сервиса.

### Отложено до следующих этапов (реализовано в консоли main.py)
* создание новых документов, категорий и пользователей через формы;
* загрузка и прикрепление новых версий файлов;
* подписание версии документа электронной подписью через веб;
* полнотекстовый поиск документов по названию.

## Хранение данных
Данные хранятся в JSON-файлах в директории `data/`:
* `data/categories.json`
* `data/documents.json`
* `data/users.json`
* `data/versions.json`

## Назначение модулей

### Корень проекта
* `main.py` – точка входа консольного приложения (сохранена с ПР3);
* `storage.py` – функции сериализации/десериализации данных JSON ↔ Python-объекты;
* `utils.py` – безопасный ввод данных и генерация идентификаторов;
* `models/` – классы предметной области и функции выборки по ID (`find_*_by_id`);
* `tests/` – тесты логики моделей и хранилища.

### Каталог `django/`
* `manage.py` – скрипт управления Django-проектом;
* `Document_management_service/` – главный пакет настроек (`settings.py`, корневой `urls.py`);
* `homepage/` – приложение главной страницы и вспомогательная функция генерации HTML `page()`;
* `documents/` – приложение для отображения документов;
* `categories/` – приложение для отображения категорий;
* `versions/` – приложение для отображения журнала версий.

## Запуск приложения

### Веб-версия (Django):
Перейдите в директорию `django` и запустите сервер:
```bash
cd django
python manage.py runserver
```
После запуска откройте в браузере: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)

### Консольная версия:
Из корневой папки проекта:
```bash
python main.py
```

## Тестирование и контроль качества
Запуск автотестов:
```bash
pytest -v
```

Проверка соответствия PEP 8:
```bash
flake8 . --extend-exclude=.venv,django
```
