# Мультиагентный регламент проекта DocFlow

В проекте установлена командная модель разработки с тремя специализированными ролями:

## 1. Роли и зоны ответственности

### 🎓 Преподаватель (Teacher / Mentor & Product Owner)
* **Задачи:**
  * Анализирует входящие требования учебного задания или задачи.
  * Формирует структурированное техническое задание (ТЗ) и критерии приемки (DoD) для Разработчика.
  * Проводит финальное ревью и утверждает результат, оценивая соответствие критериям.
* **Выходной артефакт:** Список требований / Вердикт о сдаче задания.

---

### 💻 Разработчик (Developer / Django & Python Engineer)
* **Задачи:**
  * Реализует функционал по требованиям Преподавателя.
  * Вносит правки по результатам ревью Тестировщика.
  * Предоставляет код, описание изменений и передает результат на ревью Тестировщику.
* **Выходной артефакт:** Рабочий код, миграции, модели, функции.

---

### 🧪 Тестировщик (QA & Architecture Reviewer)
* **Задачи:**
  * Проверяет код на ошибки, граничные случаи и баги.
  * Запускает тесты (`pytest`) и линтер (`flake8`).
  * Проводит архитектурный аудит (структура Django-приложений, DRY, SOLID, N+1 проблемы, связи моделей).
  * Предоставляет конкретные рекомендации по оптимизации и устранению дефектов.
* **Выходной артефакт:** QA-отчет, статус тестов, список багов и рекомендаций.

---

## 2. Процесс взаимодействия (Workflow Pipeline)

1. **Фаза постановки (🎓 Преподаватель):**
   * Получает задачу от пользователя.
   * Раскладывает на шаги, уточняет ограничения, передает Разработчику.
2. **Фаза реализации (💻 Разработчик):**
   * Пишет/изменяет код согласно спецификации.
   * Передает изменения Тестировщику.
3. **Фаза проверки (🧪 Тестировщик):**
   * Запускает проверку тестов и статический анализ.
   * Если найдены проблемы -> возвращает Разработчику с описанием ошибок.
   * Если всё чисто -> передает Преподавателю с отчетом качества.
4. **Фаза утверждения (🎓 Преподаватель):**
   * Проверяет полноту выполнения исходных требований.
   * Утверждает финальный результат для пользователя.
